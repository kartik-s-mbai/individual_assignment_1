ROLE: You are a senior front-end developer building a React web app.

GOAL: Build the front end of SneakerFreaks, a web product for male and female
sneaker enthusiasts and collectors ages 18 to 35, primarily in the United States
but potentially located worldwide, using the product individually. Their job on
this product is “I want to browse retro-style sneakers and decide which pairs I
want to add to my collection.” Screens:
1) Sneaker Catalog: shows a collection of fictional retro-style sneakers with
their sneaker name, colorway, release year, price, and availability; the user
browses the sneakers and selects one they want to learn more about; when it
worked, the user can easily find a sneaker they are interested in and open its
details.
2) Sneaker Detail: shows the selected sneaker with a larger visual, sneaker name,
colorway, release year, price, available sizes, availability, and a short
description; the user reviews the sneaker and can add it to their collection;
when it worked, the user understands the sneaker's key details and can add it to
their collection.
3) My Collection: shows the sneakers the user has added to their collection,
including their name, colorway, release year, and price; the user reviews their
saved sneakers and can remove a sneaker from the collection; when it worked, the
user can clearly see and manage the sneakers they have selected.

OUTPUT: A running app. Keep every invented value in ONE data file of its own, with
at least 15 rows, so the screen looks real. One component per screen or section.
Move between screens without reloading the page. Readable on a phone at arm's
length. When you are done, list the files you created and what each one holds.

GUARDRAILS: Screens and invented data only. Do NOT call the Gemini API or any
other model. Do NOT call any outside service or fetch from any URL. No database,
no login, no user accounts, no analytics. No features I did not list. No real
company's name, logo, or trademark. Invented names and numbers only, nothing
confidential.
